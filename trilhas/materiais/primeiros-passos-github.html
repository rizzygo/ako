Primeiros passos no GitHub

Em menos de uma hora, só pelo navegador, você faz o ciclo que times de tecnologia repetem todo dia: cria um repositório, abre uma branch, faz um commit, propõe a mudança num pull request e junta tudo com um merge.

1. As palavras que você vai usar

O Git é o programa que guarda o histórico do código. O GitHub é um site que hospeda projetos com Git e permite que várias pessoas trabalhem juntas. Nesta lição você usa só o site. O Git no terminal fica para depois.

PalavraO que é
RepositórioA pasta do projeto, com todos os arquivos e o histórico de mudanças
CommitUma mudança salva no histórico, com uma mensagem dizendo o que mudou
BranchUma linha de trabalho paralela. Você mexe nela sem afetar a versão principal
mainO nome mais comum da branch principal, a versão "oficial" do projeto
Pull requestUm pedido para juntar as mudanças de uma branch em outra, com espaço para revisão e conversa
MergeO ato de juntar as mudanças de uma branch em outra
READMEO arquivo de apresentação do projeto, que o GitHub mostra na página inicial do repositório

A interface do GitHub está em inglês. Nesta lição, o nome de cada botão aparece assim: New repository, do jeito que você vai encontrar na tela.

2. O ciclo completo, passo a passo

Crie sua conta

Em github.com, clique em Sign up e siga as instruções. Escolha o nome de usuário com cuidado: ele vira o endereço do seu portfólio, como github.com/seu-nome. Prefira algo profissional, próximo do seu nome.

Ative também a verificação em duas etapas (2FA) nas configurações da conta. Com ela, além da senha, o GitHub pede um código gerado no seu celular. Assim, ninguém entra na sua conta só porque descobriu a senha. O GitHub exige a 2FA de quem contribui com código.

Crie um repositório

  1. No canto superior direito de qualquer página, abra o menu com o sinal de mais e clique em New repository.
  2. Em Repository name, digite ola-mundo.
  3. Escreva uma descrição curta, como "Meu primeiro repositório no GitHub".
  4. Deixe o repositório como público (Public).
  5. Ligue a opção Add README, para o repositório já nascer com um arquivo de apresentação.
  6. Clique em Create repository.
Antes de criarUm repositório público pode ser visto por qualquer pessoa na internet, inclusive o histórico de mudanças. Nunca coloque ali senhas, chaves, telefone, CPF ou endereço. Mesmo apagando depois, o conteúdo pode continuar no histórico.

Crie uma branch

Em vez de mexer direto na main, você vai trabalhar numa branch. É assim que times evitam que uma mudança pela metade quebre a versão principal.

  1. Na página do repositório, clique no botão que mostra main, acima da lista de arquivos.
  2. No campo Find or create a branch..., digite minha-apresentacao.
  3. Clique em Create branch.

O botão agora mostra minha-apresentacao. Tudo o que você fizer daqui em diante fica nessa branch.

Faça um commit

  1. Com a branch minha-apresentacao selecionada, clique no arquivo README.md.
  2. Clique no ícone de lápis, no canto superior direito do arquivo, para editar.
  3. Escreva uma apresentação curta: quem você é, o que está estudando e o que quer aprender. A parte 3 mostra como formatar.
  4. Clique na aba Preview para ver como vai ficar.
  5. Clique em Commit changes....
  6. Em Commit message, escreva o que mudou, por exemplo "Adiciona minha apresentação no README".
  7. Confirme que está marcada a opção de commit direto na branch minha-apresentacao e clique em Commit changes.

Pronto: sua mudança está salva no histórico da branch, mas a main continua igual. Confira trocando a branch de volta para main no mesmo botão.

Abra um pull request

  1. Volte para a página inicial do repositório. Deve aparecer um aviso amarelo com o botão Compare & pull request. Clique nele.
  2. Se o aviso não aparecer, abra a aba Pull requests, clique em New pull request e escolha as branches como no passo seguinte.
  3. Confira as branches: base deve ser main (para onde a mudança vai) e compare deve ser minha-apresentacao (de onde ela vem).
  4. Dê um título claro e, na descrição, conte o que mudou e por quê.
  5. Clique em Create pull request.

Num time, este é o momento em que outra pessoa revisa sua mudança, comenta e pede ajustes. É uma das melhores formas de aprender com quem tem mais experiência.

Revise e faça o merge

  1. Abra a aba Files changed. Ela mostra exatamente o que mudou: linhas novas em verde e removidas em vermelho. Revisar o próprio pull request antes de pedir revisão é um bom hábito.
  2. Volte para a aba Conversation e clique em Merge pull request.
  3. Clique em Confirm merge.
  4. O GitHub oferece o botão Delete branch. Pode apagar: as mudanças já estão na main, e o histórico guarda tudo.

Confira que deu certo

  • A página inicial do repositório, na main, mostra a sua apresentação.
  • Clicando no número de commits, perto da lista de arquivos, você vê o histórico: o commit inicial, o seu commit e o merge.
  • Na aba Pull requests, em Closed, está o seu primeiro pull request concluído.
Repita o cicloFaça mais uma vez, agora criando um arquivo novo com Add file e Create new file, numa branch nova. Na segunda vez o ciclo já fica natural.

3. Escrever no README com Markdown

O README usa Markdown, um jeito simples de formatar texto com símbolos. O GitHub transforma os símbolos em formatação.

Você escreveAparece como
# Olá, eu sou a AnaUm título grande
## O que estou estudandoUm subtítulo
**Linux** e **redes**Texto em negrito
- GitUm item de lista
[Meu LinkedIn](https://...)Um link
`ls -l`Um trecho de código
Exemplo de apresentação para usar como ponto de partida 
# Olá, eu sou a Ana

Estou começando em tecnologia e estudando a trilha Primeiros passos em TI.

## O que estou estudando
- Terminal e Linux
- Git e GitHub
- Python

## O que quero aprender
Infraestrutura e cloud.

Troque pelos seus dados. Lembre que o repositório é público: deixe de fora informações pessoais.

4. Bônus: o README do seu perfil

Se você criar um repositório público com exatamente o mesmo nome do seu usuário, com um README, o GitHub mostra esse README no topo do seu perfil. Quem visita seu perfil, inclusive recrutadores, vê esse texto logo de cara.

  1. Crie um repositório novo com o nome igual ao seu usuário. O GitHub avisa que é um repositório especial.
  2. Deixe público e ligue a opção Add README.
  3. Escreva uma apresentação curta, com o que você estuda e links para seus projetos.

5. Git no terminal e projetos abertos

  • Aprenda os mesmos passos no terminal com git clone, git add, git commit e git push. O livro Pro Git, em português, cobre isso nos capítulos 1 a 3.
  • Contribua com um projeto aberto. A Iniciativa Ako aceita contribuições de quem está começando, e o guia de contribuição explica o passo a passo pelo navegador.
Para fixarExplique para alguém a diferença entre commit, branch e pull request, usando o seu repositório como exemplo. Depois, marque no tópico que você ensinou alguém.
