A nuvem no seu computador

Clicar no painel é ótimo para conhecer. Para repetir sem errar, é o terminal. E para errar à vontade sem pagar nada, existem emuladores que fingem ser a nuvem dentro do seu computador. Igual o kind faz com o Kubernetes.

2. Emuladores são a nuvem de mentirinha

Um emulador é um programa que responde como o serviço da nuvem, mas roda no seu computador. Você aponta a CLI ou o código para um endereço local e treina sem conta, sem cartão e sem medo.

EmuladorImitaCusto e cadastro
MotoVários serviços da AWS, como S3, DynamoDB, Lambda, SQS e IAMAberto (Apache-2.0), sem cadastro
LocalStackMais de 30 serviços da AWS no plano gratuitoPlano Hobby gratuito, com conta e só para uso não comercial
DynamoDB localDynamoDBGratuito, feito pela AWS, em Java ou Docker
AWS SAM CLILambda, rodando num contêinerGratuito
gcloud beta emulatorsFirestore, Datastore, Pub/Sub, Bigtable e SpannerGratuito, vem com a gcloud (em beta)

Teste com o Moto, em Docker:

docker run --rm -p 5000:5000 motoserver/moto
export AWS_ACCESS_KEY_ID=teste AWS_SECRET_ACCESS_KEY=teste AWS_DEFAULT_REGION=us-east-1
aws --endpoint-url http://localhost:5000 s3 mb s3://treino
aws --endpoint-url http://localhost:5000 s3 ls

As chaves teste são de mentira, de propósito. O emulador aceita qualquer uma, e assim nenhuma chave de verdade sai do lugar.

Teste o Firestore do Google:

gcloud beta emulators firestore start --host-port=localhost:8080

Em outro terminal, faça o seu código usar FIRESTORE_EMULATOR_HOST=localhost:8080. Os dados ficam na memória e somem quando o emulador para.

Emulador não é a nuvemEle não cobre todos os serviços nem todos os detalhes, como permissões e limites. Use para treinar e testar rápido. Antes de confiar, rode pelo menos uma vez na nuvem de verdade.

3. Terraform cria e apaga com um comando

Com Terraform, a infraestrutura vira arquivo. Você escreve o que quer, o Terraform mostra o plano e aplica. No fim, apaga tudo.

O mesmo bucket nas duas nuvens:
# AWS
resource "aws_s3_bucket" "fotos" {
  bucket = "mel-da-zumi-fotos-seu-nome"
}

# Google Cloud
resource "google_storage_bucket" "fotos" {
  name     = "mel-da-zumi-fotos-seu-nome"
  location = "SOUTHAMERICA-EAST1"
}
terraform init
terraform plan
terraform apply
terraform destroy
  • plan é a revisão. Leia sempre. Uma linha de destroy que você não esperava é o sinal para parar.
  • O arquivo de state guarda o que foi criado e pode ter segredo. Ponha no .gitignore.
  • Dá até para apontar o provider da AWS para o Moto ou o LocalStack e treinar Terraform sem conta.

4. O ciclo de estudo que não gasta

  1. Treine o comando ou o código no emulador.
  2. Escreva em Terraform.
  3. Rode na nuvem de verdade, com o alerta de orçamento ligado.
  4. Confira que funciona e tire o print para o portfólio.
  5. terraform destroy.

5. Missão final

1. Um bucket, três lugares

Crie o mesmo bucket no Moto, na AWS e no Google Cloud, só pelo terminal. Apague os três.

2. Firestore sem conta

Suba o emulador do Firestore e grave um documento pedidos/1 com um script em Python ou Node.

3. Terraform nas duas

Escreva o bucket da parte 3 em Terraform, aplique nas duas nuvens, mude uma configuração, leia o plan e destrua tudo.

Para fixarMostre para alguém o terraform plan e explique, linha por linha, o que ia acontecer. Se a pessoa entender, você entendeu.
