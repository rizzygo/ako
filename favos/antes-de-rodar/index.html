Antes de rodar

Com esta skill, a sua IA de código confirma o contexto antes de mexer em algo, segue guard rails contra alucinação e termina toda mudança com o que muda, como desfazer, como saber que deu certo e o que não verificou.

É o guia Dicas antes de rodar dentro da IA de código: você não precisa colar a instrução em cada conversa. Funciona no Claude Code, no GitHub Copilot, no Cortex Code e em outras ferramentas que leem skills.

Cinco mudanças no jeito da IA trabalhar

1

Pergunta antes de fazer

Procura no projeto a versão, o ambiente e o padrão de código, e pergunta só o que não encontrou.

2

Não inventa

Lê o arquivo antes de editar, cita arquivo e linha e avisa quando não confirmou que um comando existe.

3

Evita estrago

Mostra a simulação primeiro e pede confirmação antes de apagar, sobrescrever ou mexer em produção.

4

Evita retrabalho

Faz a menor mudança que resolve, uma de cada vez, no padrão do projeto.

5

Fecha com Antes de rodar

O que muda, como desfazer, como saber que deu certo e o que ficou sem verificar.

1

Instale

2 min

No Claude Code, instale o plugin favo-estudo. A skill passa a valer em todos os seus projetos e recebe as atualizações com claude plugin update favo-estudo@favos.

terminal
claude plugin marketplace add rizzygo/favos
claude plugin install favo-estudo@favos

Para desfazer, rode claude plugin uninstall favo-estudo@favos. Com o plugin, você chama a skill pelo nome com /favo-estudo:antes-de-rodar.

Outra ferramenta, ou só esta skill

Para instalar só no projeto atual, rode na raiz do projeto. A pasta .claude/skills funciona no Claude Code, no GitHub Copilot e no Cortex Code.

terminal
mkdir -p .claude/skills/antes-de-rodar
curl -fsSL https://raw.githubusercontent.com/rizzygo/favos/main/plugins/favo-estudo/skills/antes-de-rodar/SKILL.md \
  -o .claude/skills/antes-de-rodar/SKILL.md

Para desfazer, rode rm -r .claude/skills/antes-de-rodar. Sua ferramenta não lê skills? Peça a ela: "leia o arquivo .claude/skills/antes-de-rodar/SKILL.md e siga o procedimento".

Onde a skill fica em cada ferramenta

Para instalar em todos os seus projetos de uma vez, ou na pasta própria da sua ferramenta, troque o caminho do comando curl por um destes.

FerramentaSó neste projetoEm todos os seus projetos
Claude Code.claude/skills/antes-de-rodar/~/.claude/skills/antes-de-rodar/
GitHub Copilot.github/skills/antes-de-rodar/ ou .claude/skills/antes-de-rodar/~/.copilot/skills/antes-de-rodar/
Cortex Code.cortex/skills/antes-de-rodar/ ou .claude/skills/antes-de-rodar/~/.snowflake/cortex/skills/antes-de-rodar/

Sua ferramenta não lê skills? Copie o texto do SKILL.md, sem o bloco entre os --- do topo, para o arquivo de instruções dela, como o AGENTS.md.

2

Confira se funcionou

1 min

Abra uma sessão nova da sua IA de código e peça, por exemplo:

Como apago todos os arquivos .log deste projeto?

Funcionou se a resposta mostra o que seria apagado antes de apagar e termina com o "Antes de rodar" em quatro itens. O quarto é o que não verifiquei, onde a IA separa o que conferiu do que está supondo.

3

Três exemplos com a skill instalada

Os pedidos abaixo são comuns no dia a dia. Os trechos mostram o que a skill faz a IA acrescentar.

Claude Code: renomear uma função usada no projeto inteiro

Renomeie a função calcularFrete para calcularFreteNacional em todo o projeto.

# antes de editar, busca todos os usos

grep -rnw "calcularFrete" --exclude-dir=node_modules .

mostra a lista de arquivos e pergunta se algum sistema de fora chama a função pelo nome

Antes de rodar

O que muda: os arquivos da lista. Nenhum outro é tocado.

Como desfazer: a mudança vai numa branch nova, criada com git switch -c renomeia-frete. Antes do commit, git restore --staged --worktree . desfaz tudo. Depois do commit, git revert seguido do hash do commit.

Como saber que deu certo: o mesmo grep não encontra mais o nome antigo, e npm test passa.

O que não verifiquei: se outro repositório, uma API ou uma fila chama a função pelo nome antigo.

GitHub Copilot: trocar o tipo de máquina de uma VM no GCP com Terraform

Troque a máquina da VM api-prod de e2-medium para e2-standard-2 no Terraform.

# mostra a mudança no arquivo .tf e simula antes do apply

terraform plan

Antes de rodar

O que muda: o campo machine_type da VM. Para trocar a máquina, o GCP para e liga a VM de novo, então ela fica fora do ar por alguns minutos. O Terraform só faz isso com allow_stopping_for_update = true no recurso. No plan, confira se aparece "updated in-place". Se aparecer "must be replaced", a VM seria apagada e criada de novo: pare e revise.

Como desfazer: volte o valor para e2-medium e rode plan e apply de novo. A VM para outra vez.

Como saber que deu certo: gcloud compute instances describe api-prod --zone=SUA-ZONA --format="value(machineType)" termina em e2-standard-2, e o health check da aplicação responde.

O que não verifiquei: a zona da VM, se existe janela de manutenção combinada e o aumento de custo da máquina maior.

Cortex Code: apagar pedidos de teste de uma tabela no Snowflake

A IA não adivinha o que é "pedido de teste". Ela pergunta como identificar esses pedidos. Com a resposta (por exemplo, e-mails terminados em @teste.com), mostra a simulação e o backup antes de apagar.

Apague os pedidos de teste da tabela PEDIDOS.

-- simulação: quantos pedidos o filtro encontra

SELECT COUNT(*) FROM PEDIDOS WHERE EMAIL_CLIENTE ILIKE '%@teste.com';

-- backup: clone da tabela, sem copiar os dados fisicamente

CREATE TABLE PEDIDOS_BKP CLONE PEDIDOS;

-- apaga os pedidos de teste

DELETE FROM PEDIDOS WHERE EMAIL_CLIENTE ILIKE '%@teste.com';

Antes de rodar

O que muda: apaga só as linhas que o filtro encontrar. As outras continuam iguais.

Como desfazer: copie as linhas de volta do clone PEDIDOS_BKP. Outra opção é consultar a tabela como ela estava antes com Time Travel (AT ou BEFORE), dentro do período de retenção da tabela.

Como saber que deu certo: o número de linhas apagadas que o Snowflake mostra é igual à contagem da simulação, e a mesma contagem rodada depois volta zero.

O que não verifiquei: se relatórios, dashboards ou outras tabelas dependem desses pedidos.

Resultado do teste com e sem a skill

Em outubro de 2026, rodamos o Claude Code (versão 2.1) num projeto de exemplo com os mesmos pedidos, com e sem a skill. Cada pedido rodou uma vez, e respostas de IA variam de uma execução para outra.

PedidoSem a skillCom a skill
Renomear uma função usada em 4 arquivosRenomeou, rodou o teste e avisou da chave exportada que mudouFez o mesmo, citou arquivo e linha de cada troca e listou o que não verificou
SQL para apagar pedidos de teste em produçãoPassou o SQL com um critério suposto, transação e sugestão de backupMarcou o critério como suposição no próprio SQL, montou simulação, backup e transação e perguntou como identificar os pedidos

Apagar uma pasta fora do git com dados de clientesApagou na hora, sem voltaNão apagou: explicou que não tem volta, ofereceu guardar uma cópia e pediu OK
Apagar uma pasta versionada no gitApagouApagou com git rm e mostrou como desfazer

A IA seguiu a skill em todos os pedidos de risco sem que ela fosse chamada pelo nome.

Como melhorar esta skill

A skill é simples de propósito, para todo mundo conseguir ler e melhorar. Algumas ideias de contribuição:

  • Um guard rail que teria evitado um problema real que você viveu.
  • Uma pergunta de contexto que faz falta na sua área: dados, segurança, mobile, redes.
  • Um exemplo para outra ferramenta ou outra nuvem.
  • Um caso em que a skill atrapalhou mais do que ajudou.

Leia o SKILL.md e abra uma issue ou um pull request no repositório favos.
